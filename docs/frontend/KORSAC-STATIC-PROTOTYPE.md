# KORSAC — Static UI Prototype Foundation v1

## Назначение

Прототип фиксирует визуальную основу KORSAC перед переносом в Bitrix:
типографику, адаптивную сетку, компоненты, состояния и подачу PLAY 1440.
`index.html` — страница навигации по прототипам; `ui.html` — визуальный инвентарь;
`product.html` — главный продуктовый стенд. Это исходный HTML, без генерации
страниц в браузере или этапа компиляции.

Источники решений:

- [Бренд](../brand/KORSAC-BRAND-GUIDE.md).
- [PLAY 1440 baseline](../product/KORSAC-PLAY-1440-SPEC-v0.1.md).
- [Архитектура PLAY](../product/KORSAC-PLAY-ARCHITECTURE.md).
- [Архитектура MINI](../product/KORSAC-MINI-ARCHITECTURE.md).

## Файлы и запуск

```text
prototype/
├── index.html
├── ui.html
├── product.html
└── assets/
    ├── css/
    │   ├── tokens.css
    │   ├── base.css
    │   ├── layout.css
    │   ├── components.css
    │   └── pages.css
    ├── js/prototype.js
    └── images/README.md
```

Откройте `prototype/index.html` непосредственно в браузере. Ссылки на CSS/JS
относительные; `fetch`, ES-модули и внешние ресурсы не нужны.

Необязательный сервер из корня репозитория:

```sh
python3 -m http.server 8000 --bind 127.0.0.1 --directory prototype
```

Для внутренней проверки запросите `/index.html`, `/ui.html`, `/product.html`.
Сборка и установка пакетов не требуются. Прототип рассчитан на актуальные
Chrome, Edge, Firefox и Safari; проверки в конкретных браузерах перечисляются
в PR, поддержка остальных не должна выдаваться за выполненное тестирование.

## Токены и CSS

`tokens.css` содержит утверждённую рабочую палитру `--korsac-*`, семантические
роли `--k-*`, размеры текста, интервалы, радиусы, тень и ширину контейнера.
Компоненты используют семантические роли, а не повторяют цвета. Electric Blue
остаётся акцентом выбора; для белого текста CTA применяется более тёмная
производная заливка `--k-accent-fill`, сохраняющая контраст. Copper — небольшая
деталь паспорта и нумерации, а не вторая CTA-заливка.

Типографика: display, H1–H3, body-lg/body/body-sm, caption, label, price-lg/price,
technical. Шрифты берутся только из локального системного стека. Inter, Manrope
и Geist — будущие fallback-направления, загрузки web fonts нет.

Префикс классов — `k-`. Компоненты (`k-button`, `k-option`, `k-price`,
`k-accordion`, `k-dialog`) независимы от страницы. Модификаторы — `--secondary`,
`--image` и аналогичные; `k-state-*` только для статических образцов состояния
в UI Kit. Реальные `:hover`, `:active`, `:focus-visible`, `:checked` работают
отдельно. Основные слои:

| Файл | Ответственность |
| --- | --- |
| tokens.css | Значения и семантические роли |
| base.css | Reset, текст, ссылки, focus, reduced motion |
| layout.css | Контейнер, grid, stack, cluster, shell |
| components.css | Повторно используемые элементы и состояния |
| pages.css | Компоновка UI Kit и продукта |

## Адаптивность и доступность

Контейнер ограничен 1360 px, поля адаптивны. Grid использует `minmax` с
ограничением на ширину контейнера, поэтому карточки не задают минимальную
ширину страницы. На 600 px упрощаются мелкие карточки; с 900 px появляются
две колонки hero и горизонтальная навигация; с 1100 px сводка конфигурации
становится боковой и sticky. На меньших экранах сводка остаётся в обычном потоке.
Горизонтальный скролл вкладок находится внутри tablist и не расширяет страницу.

Проверяем ширины 320, 375, 768, 1024, 1280 и 1440 px, читаемость CTA, цен,
корпусов и отсутствие скролла всей страницы. Есть skip link, один H1,
явные labels, семантические кнопки и нативные radio/checkbox/select.
Минимальная высота основных контролов — 44 px. Фокус виден; анимации и плавный
скролл отключаются при `prefers-reduced-motion: reduce`.

Radio-группы работают через обычные HTML-контролы и CSS `:checked`, включая
клавиши стрелок. Вкладки поддерживают Left/Right, Home/End и roving tabindex.
Accordion использует `aria-expanded`/`aria-controls`. Нативный `<dialog>`
обеспечивает модальность, удержание фокуса, Escape и inert-фон; JS возвращает
фокус к открывшему контролу и блокирует прокрутку фона. Toast использует
`role=status`, не исчезает по таймеру и закрывается кнопкой.

Без JS остаются доступны страницы, конфигурационные radio/select/checkbox
и содержимое всех вкладок и ответов. Диалоги и переключение вкладок требуют JS.

## Границы JavaScript и данные макета

`prototype.js` отвечает только за вкладки, accordion, dialog/drawer и показ
уведомлений. Статическая сводка подписана как пример базовой конфигурации:
она не отражает изменения выбора. Все цены и дельты — демонстрационные числа,
не коммерческое предложение. Никакой арифметики компонентов нет.

Кнопка «Добавить в корзину» открывает информацию о прототипе; счётчик корзины
и заказы отсутствуют. UI Kit показывает образцы сообщений об успехе и ошибке,
но они не означают выполнение покупки или пересчёта. Нет API, localStorage,
авторизации, поиска, фильтров, аналитики и Bitrix-зависимостей.

CPU/GPU фиксированы: Ryzen 7 9700X и RTX 5070 12 ГБ. Основные пользовательские
опции — RAM 32/64 ГБ, SSD и корпус. OS/software/service представлены как
будущие визуальные группы и требуют согласования; недопущенные варианты
disabled. Корпуса из shortlist — кандидаты, а не уже утверждённые физические
SKU; выбор LANCOOL 217 в макете не утверждает его производственным default.
MINI — отдельный товар, не вариант корпуса PLAY 1440.

Wordmark — временный текст, не финальный логотип. Рамки изображений и wireframe
не являются фотографиями. SYSTEM ID — визуальная идея с вымышленным номером.
FPS, температуры, шум, срок гарантии и доставка не выдумываются: соответствующие
блоки отмечены как ожидающие измерений или согласования. Описанная
последовательность сборки — рабочий процесс, а не утверждённый сервисный SLA.

## Будущий перенос в Bitrix

| Основа прототипа | Будущая точка интеграции |
| --- | --- |
| Header/footer | `local/templates/korsac/header.php` / `footer.php` |
| Карточка продукта | шаблон `bitrix:catalog.section` |
| Hero, описание, характеристики | шаблон `bitrix:catalog.element` |
| Визуальные option controls | тема/styles `kk.korsac.configurator-renderer` |
| Группы и сводка конфигурации | `kk:korsac.configurator` |
| Будущий интерфейс корзины | шаблон `Bitrix sale.basket.basket` |

На этапе переноса shell-дублирование убирается в header/footer. Имена,
физические SKU, разрешённые варианты, наличие, цена и состав сводки поступают
из реальных данных. Дельты и окончательную цену отдаёт авторитетный серверный
pricing engine. Корзина сохраняет проверенный backend snapshot конфигурации.
Числа и статические тексты этого прототипа нельзя копировать как бизнес-логику,
контракт SKU, production-статусы или гарантийные обязательства.

## Проверка перед PR

- Все три страницы открываются через HTTP и `file://`, локальные ресурсы целы.
- Нет ошибок консоли и внешних запросов.
- Ширины 320/375/768/1024/1280/1440 не создают горизонтальный скролл страницы.
- Tab, Shift+Tab и стрелки позволяют выбрать radio, вкладки и обычные контролы.
- Accordion меняет `aria-expanded`, содержимое появляется и скрывается.
- Modal/drawer закрываются кнопкой, Escape и фоном; фокус возвращается.
- Выбор опций не изменяет статическую цену и не вызывает сеть.
- Reduced motion отключает spinner и переходы.
- Ссылки, labels, IDs, заголовки и `aria-controls` согласованы.
- `git diff --check` проходит; исходная архитектурная документация не изменена.

Скриншоты desktop/mobile UI Kit и PLAY 1440 — [материалы визуального ревью](review/README.md),
не runtime-зависимости. Проверка в одном браузере не заменяет будущий ручной
приёмочный прогон во всех целевых браузерах.
