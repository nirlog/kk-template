03 / Automation recovery

Условия соблюдены — операцию можно повторить

Названия статусов справочные. Backend сопоставляет стабильные CODE с настроенными условиями и отдаёт доступность действий. Кнопки макета ничего не выполняют.

01

Создать System

Выполнено автоматически · 2 из 2

Заказ-макет: PLAY 1440 × 2, монитор × 1. Оба компьютера имеют System; монитор не создаёт System. Повторное создание недоступно.

02

Подготовить паспорт

Ожидалось, но не выполнено

KS-2610-0013: статус соответствует READY_FOR_DELIVERY, обязательные слоты подтверждены, PUBLIC_ID отсутствует. Повторный вызов использует существующий PUBLIC_ID.

03

Активировать паспорт

Ожидает передачи

KS-2610-0013: физическая передача не подтверждена. Подготовка сама по себе не активирует паспорт.

Другие состояния: создание / передача / подготовка

04

До согласования

Создание недоступно

Заказ ещё не достиг разрешённого условия; backend учитывает историю, а не только текущую строку статуса.

05

Пропущено создание единицы

2 из 3 компьютеров имеют System

Отдельный макет заказа с количеством 3: условие создания ранее достигнуто. Можно создать только недостающую единицу, не дубликаты существующих.

06

Пропущена активация

PREPARED · передача подтверждена

Отдельный сценарий восстановления: публичный идентификатор существует, первая положительная передача уже зафиксирована. Дату и гарантию повторно не сдвигать.

07

Уже подготовлен

PREPARED · публичный доступ ожидает передачи

KS-2610-0014 · отдельный prepared-макет. PUBLIC_ID уже существует. Повторно генерировать идентификатор нельзя; можно пересоздать только представление QR.

Сценарии независимы от двух основных System выше. Переключение или просмотр не меняет их состояния.

Расширенная гарантия до активации

Это выбор до активации; дата окончания здесь не вычисляется. Backend зафиксирует применённые месяцы и итоговый срок при первой передаче.

Публичный паспорт получает только текущие ACTIVE-названия. S/N, внутренние записи и снятые компоненты остаются здесь. Комплектующие подтверждает сотрудник, не текущий Product.

Подтверждение перед READY_FOR_DELIVERY · пример CUSTOM

Индивидуальная сборка · отдельный макет без каталожной модели. Предзаполнение заказа не подтверждает физическую установку.

  • CPU — обязательный слот, подтверждён
  • Дискретный GPU — не применимо: интегрированная графика
  • SSD 1 — обязательный, подтверждён
  • SSD 2 — необязательный, не установлен
  • OTHER — дополнительные записи допускаются по контексту

Нет глобального требования восьми компонентов. Обязательные, необязательные и «не установлено / не применимо» слоты задаёт модель, снимок заказа или определение CUSTOM.
